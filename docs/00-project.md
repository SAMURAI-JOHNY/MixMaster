### Назначение и решаемая проблема

MixMaster — веб-приложение для каталога коктейлей и рецептов. Оно помогает любителям находить и сохранять рецепты, а барменам — вести каталог, ингредиенты и составы напитков. Проблема: разрозненные рецепты и отсутствие ролевого разделения между просмотром и управлением каталогом.

### Целевые пользователи и роли

| Роль | Кто | Основные возможности |
|------|-----|----------------------|
| **Любитель** (`любитель`) | Пользователь-энтузиаст | Регистрация/вход, просмотр каталога и рецептов, отметка приготовленных коктейлей, поиск во внешнем TheCocktailDB |
| **Бармен** (`бармен`) | Куратор каталога | Всё доступное любителю + создание/редактирование коктейлей, рецептов и ингредиентов, загрузка изображений |

Дополнительно система взаимодействует с внешней API **TheCocktailDB**.

### Три основные функции

1. Просмотр каталога коктейлей и карточек рецептов.
2. Управление каталогом (коктейли, рецепты, ингредиенты) ролью «бармен».
3. Учёт приготовленных коктейлей пользователем и поиск рецептов во внешнем API.

## 2. Структура проекта

Исходный код организован как монорепозиторий `frontend/` + `backend/` (вместо единого каталога `src/`). Каталоги `src/` и `tests/` в корне содержат указатели на фактическое расположение кода и тестов (требование структуры курса).

### Каталоги и модули

| Путь | Назначение |
|------|------------|
| `frontend/src/` | UI: страницы, компоненты, API-клиенты |
| `frontend/e2e/` | E2E-тесты Playwright |
| `backend/main.py` | Точка входа FastAPI-приложения |
| `backend/api/routers/` | HTTP-роутеры (auth, cocktails, recipes, ingredients, upload, prepared, SEO, external) |
| `backend/crud/` | Операции с БД |
| `backend/database/` | Модели SQLAlchemy, сессия БД |
| `backend/schemas/` | Pydantic-схемы |
| `backend/services/` | Клиент TheCocktailDB и др. |
| `backend/core/` | Хранилище S3/MinIO |
| `backend/tests/` | Модульные и интеграционные тесты |
| `docker/` | Nginx gateway, вспомогательные скрипты |
| `docs/` | Документация курса и паспорта |
| `scripts/` | Скрипты проверки запуска |
| `.github/workflows/` | CI |

### Точки входа

- **Backend:** `backend/main.py` → `uvicorn main:app`.
- **Frontend (dev):** `frontend` → `npm start` (порт 3000).
- **Полный стек:** `docker compose up` → HTTP `http://localhost:8080` (gateway).

### Внешние зависимости и сервисы

| Сервис | Назначение |
|--------|------------|
| PostgreSQL | Основное хранение сущностей |
| MinIO | Объекты (аватары, изображения коктейлей/ингредиентов) |
| TheCocktailDB | Поиск внешних рецептов по имени |
| (опц.) браузерный доступ к MinIO | Presigned URL на `127.0.0.1:9000` |

### Хранение данных

- Реляционные сущности — PostgreSQL (таблицы `users`, `cocktails`, `recipes`, `ingredients`, `recipe_ingredients`, `prepared_cocktails`, `file_attachments`, `refresh_tokens`).
- Файлы — S3-совместимое хранилище MinIO, метаданные в `file_attachments`.

### Конфигурация

- Корневой `.env` (из `.env.example`) для Docker Compose.
- `backend/.env` / переменные окружения: `DATABASE_URL`, `JWT_SECRET_KEY`, `STORAGE_PROVIDER`, `S3_*`, `CORS_ORIGINS`, `COCKTAILDB_BASE_URL`, `PUBLIC_SITE_URL`.
- Frontend build-args: `REACT_APP_API_BASE_URL`, `REACT_APP_SITE_URL`.

## 5. Наблюдения о проблемах проекта

Оформляются GitHub issues (метки `question` / `bug`). Краткое содержание:

1. **Опечатка в имени модуля `recieps`** — путь `backend/api/routers/recieps.py` и пакет `crud/recieps` снижают читаемость; нужен план переименования без поломки API.
2. **Healthcheck недоступен через gateway** — `/health` есть у backend, но Nginx проксирует только `/api/`; внешняя проверка здоровья через публичный URL осложнена.
3. **Зависимость от hosts/`minio` для presigned URL** — загрузка файлов из браузера требует `127.0.0.1 minio` или отдельного `S3_PRESIGN_ENDPOINT_URL`; порог входа для новых разработчиков выше.
4. *(дополнительно)* Расхождение версий Python: локально 3.13, в CI — 3.12.

## 6. Выполнимость и план на семестр

### 6.1 Исследование выполнимости (риски)

| Риск | Тип | Вероятность | Последствия | Снижение |
|------|-----|-------------|-------------|----------|
| Сложность S3/MinIO и CORS/presign | Технический | Средняя | Блокировка загрузок файлов | Локальный MinIO в compose; документированный smoke; упрощённый путь без S3 для части сценариев |
| Нестабильность / лимиты TheCocktailDB | Внешний | Средняя | Поиск внешних рецептов недоступен | Уже есть degraded-режим и моки в тестах |
| Объём работ при индивидуальной занятости | Организационный | Средняя | Срыв сроков ЛР | Жёсткий scope семестра (F1–F8); отложить «nice to have» |
| Защита `main` / процесс PR без `gh` на машине | Организационный | Низкая | Задержки сдачи | Установить GitHub CLI; чеклист настроек репозитория |
| Секреты и платные облака | Внешний | Низкая | Нет: MinIO и Postgres в Docker бесплатны | Не использовать платный S3 в семестре |

**Вывод:** проект выполним за семестр: роли и сущности уже есть, стек знаком автору, запуск через Compose воспроизводим.
