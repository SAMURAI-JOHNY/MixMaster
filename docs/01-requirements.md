## 1. О приложении

### 1.1. Задача

**MixMaster** — веб-приложение для каталога коктейлей и рецептов. Любители ищут рецепты и отмечают приготовленные напитки, бармены ведут каталог (коктейли, рецепты, ингредиенты) и загружают изображения. Есть поиск во внешнем сервисе TheCocktailDB.

### 1.2. Роли

| Роль | Кто | Возможности |
|------|-----|-------------|
| Гость | Без аккаунта | Просмотр каталога и рецептов |
| Любитель | Зарегистрированный пользователь | То же + приготовленные коктейли, внешний поиск, профиль |
| Бармен | Куратор каталога | То же + создание и правка коктейлей, рецептов, ингредиентов, загрузка картинок |

### 1.3. Что уже умеет приложение

- регистрация и вход с выбором роли;
- каталог: поиск, фильтр по категории, пагинация;
- карточка рецепта/коктейля;
- CRUD коктейлей, рецептов и ингредиентов для бармена;
- отметка «приготовил» и страница «Мои приготовленные»;
- поиск в TheCocktailDB (если сервис недоступен — сообщение об ошибке, каталог работает);
- загрузка изображений в MinIO (аватар, коктейль, ингредиент);
- SEO: sitemap, JSON-LD.

### 1.4. Термины

| Термин | Смысл |
|--------|--------|
| Пользователь | Учётная запись с ролью «любитель» или «бармен» |
| Коктейль | Напиток в каталоге: название, описание, инструкция, изображение, категория |
| Рецепт | Вариант приготовления коктейля: тип (IBA / свой), описание, состав, признак завершённости |
| Ингредиент | Компонент рецепта: название, объём, изображение |
| Приготовленный коктейль | Отметка, что пользователь приготовил коктейль |
| TheCocktailDB | Внешний API справочника коктейлей |

## 2. Требования к функционалу и ограничения

### 2.1. Функциональные требования (FR)

#### FR-1. Регистрация и вход

Пользователь (гость) может зарегистрировать учётную запись с ролью «любитель» или «бармен» и войти по имени и паролю.

| | |
|--|--|
| Приоритет | обязательно в этом семестре |
| Состояние | уже есть |
| Признак выполнения | После входа в шапке виден профиль; при неверном пароле показывается ошибка |

#### FR-2. Просмотр каталога коктейлей

Пользователь (гость, любитель или бармен) может просматривать список коктейлей с поиском по названию, фильтром по категории и постраничной навигацией.

| | |
|--|--|
| Приоритет | обязательно в этом семестре |
| Состояние | уже есть |
| Признак выполнения | На главной есть список карточек; `GET /api/v1/cocktails/` отвечает 200 и JSON |

#### FR-3. Просмотр рецепта коктейля

Пользователь (гость, любитель или бармен) может открыть карточку коктейля и увидеть описание, инструкцию и состав ингредиентов.

| | |
|--|--|
| Приоритет | обязательно в этом семестре |
| Состояние | уже есть |
| Признак выполнения | Страница `/recipe/:id` показывает данные; для несуществующего id — «не найдено» |

#### FR-4. Управление коктейлями и рецептами (бармен)

Пользователь (бармен) может создавать и редактировать коктейли и связанные рецепты, включая состав ингредиентов.

| | |
|--|--|
| Приоритет | обязательно в этом семестре |
| Состояние | уже есть |
| Признак выполнения | Новый коктейль появляется в каталоге; у любителя операции изменения отклоняются |

#### FR-5. Управление ингредиентами (бармен)

Пользователь (бармен) может просматривать, создавать, изменять и удалять ингредиенты.

| | |
|--|--|
| Приоритет | обязательно в этом семестре |
| Состояние | уже есть |
| Признак выполнения | CRUD на `/ingredients`; изменения видны в списке и при сборке рецепта |

#### FR-6. Учёт приготовленных коктейлей

Пользователь (любитель или бармен) может отметить коктейль как приготовленный и открыть список своих приготовленных.

| | |
|--|--|
| Приоритет | обязательно в этом семестре |
| Состояние | уже есть |
| Признак выполнения | После отметки запись есть на `/my-prepared`; без входа отметка не сохраняется |

#### FR-7. Поиск во внешнем TheCocktailDB

Пользователь (любитель или бармен) может искать рецепты по имени во внешнем API и видеть результаты или сообщение, что сервис недоступен.

| | |
|--|--|
| Приоритет | обязательно в этом семестре |
| Состояние | уже есть |
| Признак выполнения | При рабочем API — список совпадений; при сбое — сообщение об ошибке, локальный каталог доступен |

#### FR-8. Загрузка изображений

Пользователь (бармен) может загружать изображения коктейлей и ингредиентов, а пользователь (любитель или бармен) — изображение профиля; картинки отображаются в интерфейсе.

| | |
|--|--|
| Приоритет | обязательно в этом семестре |
| Состояние | нужно доработать |
| Признак выполнения | Допустимый файл (JPEG/PNG/WebP/GIF, в лимите размера) отображается у сущности; неверный тип или размер отклоняется. Доработка: стабильный сценарий загрузки через MinIO после `docker compose up` |

#### FR-9. Восстановление доступа

Пользователь (любитель или бармен) может восстановить доступ к учётной записи по электронной почте.

| | |
|--|--|

| Состояние | нужно сделать |

### 2.2. Ограничения (NFR)

#### NFR-1. Платформа клиента

Веб-клиент в актуальных **Chrome, Firefox и Edge** на Windows / macOS / Linux. Главная, рецепт и вход открываются без критических ошибок вёрстки.

#### NFR-2. Время ответа каталога

`GET /api/v1/cocktails/` на локальном Docker Compose при каталоге до 100 записей отвечает **не дольше 2 секунд**.

#### NFR-3. Защита учётных данных

Пароли хранятся как хеш; защищённые операции требуют JWT. Запрос на изменение каталога без прав бармена даёт 401/403.

#### NFR-4. Воспроизводимый запуск

Полный стек поднимается через **Docker Compose** по README **не более чем пятью командами** от чистого клона. Проверка: `docker compose up --build -d` и smoke-check SPA + API.

#### NFR-5. Технологический стек

Backend — **Python (FastAPI)**, frontend — **React (TypeScript)**, данные — **PostgreSQL**, файлы — **S3-совместимое хранилище** (см. `backend/`, `frontend/`, `docker-compose.yml`).

## 3. Пользовательские сценарии

### 3.1. Перечень сценариев

#### US-1. Регистрация → FR-1

Я как гость имею форму регистрации, делаю: выбираю роль, ввожу имя и пароль, подтверждаю пароль и отправляю форму, получаю учётную запись и возможность войти.

| | |
|--|--|
| Вход | username, password, confirmPassword, role (любитель / бармен) |
| Выход | пользователь создан; при занятом имени — ошибка, вторая запись не создаётся |

#### US-2. Вход → FR-1

Я как зарегистрированный пользователь имею учётную запись, делаю: ввожу имя и пароль и нажимаю «Войти», получаю сессию и профиль в шапке.

| | |
|--|--|
| Вход | username, password |
| Выход | вход выполнен, в шапке имя и роль; при неверном пароле — ошибка, токен не выдаётся |

#### US-3. Каталог → FR-2

Я как гость имею главную страницу, делаю: при необходимости ищу по названию, фильтрую по категории, листаю страницы, получаю список карточек (или пустой список).

| | |
|--|--|
| Вход | q, category, page, limit (по желанию) |
| Выход | карточки на странице; ответ API 200 с items, total, pages |

#### US-4. Карточка рецепта → FR-3

Я как гость имею id коктейля из каталога, делаю: открываю карточку, получаю описание, инструкцию и состав.

| | |
|--|--|
| Вход | id в URL `/recipe/:id` |
| Выход | страница с данными; неверный id — «не найдено» |

#### US-5. Создание рецепта → FR-4

Я как бармен имею сессию с ролью «бармен», делаю: заполняю форму коктейля/рецепта и сохраняю, получаю новый коктейль в каталоге и связанный рецепт.

| | |
|--|--|
| Вход | название, описание, инструкция, тип рецепта, состав (ingredient_id, volume_ml) |
| Выход | коктейль и рецепт в БД; карточка на главной |

#### US-6. Редактирование → FR-4

Я как бармен имею существующий коктейль, делаю: открываю редактирование, меняю поля, сохраняю, получаю обновлённые данные на карточке.

| | |
|--|--|
| Вход | сессия бармена, id коктейля или рецепта, новые значения полей |
| Выход | обновлённая карточка; без прав бармена запись не меняется |

#### US-7. Ингредиенты → FR-5

Я как бармен имею страницу `/ingredients`, делаю: создаю, изменяю или удаляю ингредиент, получаю актуальный список.

| | |
|--|--|
| Вход | сессия бармена, имя и объём ингредиента (или id для правки/удаления) |
| Выход | обновлённый список ингредиентов |

#### US-8. Отметить приготовление → FR-6

Я как любитель имею вход и открытую карточку, делаю: нажимаю «приготовил», получаю запись в «Мои приготовленные».

| | |
|--|--|
| Вход | авторизация, cocktail_id |
| Выход | запись на `/my-prepared` |

#### US-9. Список приготовленных → FR-6

Я как любитель имею хотя бы одну отметку, делаю: открываю `/my-prepared`, получаю список отмеченных коктейлей.

| | |
|--|--|
| Вход | сессия любителя |
| Выход | список коктейлей, которые этот пользователь отметил приготовленными |

#### US-10. Внешний поиск → FR-7

Я как любитель имею поле поиска TheCocktailDB, делаю: ввожу имя напитка и отправляю запрос, получаю внешние рецепты или сообщение, что сервис недоступен.

| | |
|--|--|
| Вход | строка имени |
| Выход | список из TheCocktailDB или сообщение об ошибке внешнего сервиса |

#### US-11. Загрузка изображения → FR-8

Я как бармен имею форму коктейля, делаю: выбираю файл и загружаю, получаю картинку у карточки.

| | |
|--|--|
| Вход | файл изображения |
| Выход | файл в MinIO и ссылка у сущности; неверный тип — ошибка 400, файл не сохраняется |

#### US-12. Восстановление пароля → FR-9

Я как пользователь имею email учётной записи, делаю: запрашиваю восстановление и задаю новый пароль по ссылке, получаю вход с новым паролем.

| | |
|--|--|
| Вход | email учётной записи, новый пароль по ссылке |
| Выход | вход с новым паролем; старый пароль не действует |

Приоритет: потом. Состояние: нужно сделать.

### 3.2. Примеры для трёх ключевых сценариев

#### Пример A — US-2 (вход)

| | Значение |
|--|----------|
| Вход | username = `alice`, password = `Secret123!` (аккаунт уже есть) |
| Результат | вход успешен, в шапке `alice` |

Неверные данные: password = `wrong` → сообщение об ошибке, токен не выдаётся, «приготовил» недоступно.

#### Пример B — US-5 (создание рецепта)

| | Значение |
|--|----------|
| Вход | пользователь `bob`, роль бармен; name = `Negroni`, description = `Классика на джине`; тип «Свой рецепт»; состав: Джин 30 мл, Кампари 30 мл, Вермут 30 мл |
| Результат | в каталоге есть Negroni; на карточке три ингредиента с объёмами |

Неверные данные: пустое name или роль любитель → ошибка валидации или 403; коктейль не создаётся.

#### Пример C — US-10 (внешний поиск)

| | Значение |
|--|----------|
| Вход | авторизованный пользователь, строка `margarita` |
| Результат | список совпадений из TheCocktailDB (если API доступен) |

Неверные данные: пустая строка → ошибка валидации. Если TheCocktailDB недоступен → сообщение об ошибке, локальный каталог работает.
